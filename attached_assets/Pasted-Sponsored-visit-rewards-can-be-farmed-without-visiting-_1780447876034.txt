Sponsored-visit rewards can be farmed without visiting advertisers
High
Sponsored Visit Abuse
An authenticated user can collect sponsored-visit rewards and drain advertiser budgets with a simple script, without actually browsing to the sponsor's site in a real browser session. This turns a pay-per-visit flow into a self-service credit faucet for attackers who automate many accounts or IPs.

The sponsored-visit witness chain relies on signals that are observable and replayable by the claimant instead of on a server-verifiable proof that the advertiser page was really visited. In /api/earn/sponsored/:id/begin, the server returns both the attemptToken and a valid visitUrl/VST to the authenticated caller, so the same client that wants the reward already possesses every secret needed to drive the rest of the flow (artifacts/api-server/src/routes/cashclip.ts, sponsored begin flow). In /api/earn/sponsored/r/:token, the server immediately records redirectedAt and stores a fresh witnessNonce, but also sends that nonce back in a Set-Cookie header (artifacts/api-server/src/routes/cashclip.ts:2503-2545, 2518-2520). A non-browser HTTP client can read that header directly and then send the same value back in a crafted Cookie: cc_w=... header to /api/earn/sponsored/ack/:token, which only checks the copied cookie, the caller-controlled User-Agent, the same source IP, and the VST that was already handed to the caller by /begin (artifacts/api-server/src/routes/cashclip.ts:2795-2866).

After that, /api/earn/sponsored/c/:token accepts only an HMAC derived from that same nonce plus JWT_ACCESS_SECRET, but /ack already returns the required ackToken to the attacker (artifacts/api-server/src/routes/cashclip.ts:2869-2876). The only extra gate is Sec-Fetch-Mode === "navigate" (artifacts/api-server/src/routes/cashclip.ts:3029-3045), which is just a client-supplied HTTP header and can be trivially spoofed by curl, axios, or any custom bot. Crucially, /c marks witnessedAt before redirecting and does not require the optional advertiser pixel callback at all (artifacts/api-server/src/routes/cashclip.ts:3071-3089, 3096-3101). Finally, /api/earn/sponsored/visit only requires that redirectedAt and witnessedAt exist and have aged long enough (artifacts/api-server/src/routes/cashclip.ts:3389-3419), so a script can complete the full sequence /begin -> /r -> wait -> /ack -> /c -> wait -> /visit without any genuine advertiser interaction.

Because this is a money-crediting path, the impact is direct financial abuse: attacker-controlled accounts can mint bonus balance from sponsored campaigns while delivering no real traffic to advertisers. Existing rate limits and per-account/per-IP caps reduce single-account throughput but do not prevent exploitation; they only bound each bot identity. An attacker using multiple accounts, proxies, or residential IPs can still scale this into meaningful budget drain and fraudulent reward cash-outs.
