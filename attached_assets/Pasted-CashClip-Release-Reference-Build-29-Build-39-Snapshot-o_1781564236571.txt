3. Caveats (read before shipping anything)
* OTA = JS/content only. Over-the-air updates can never carry native changes (new SDK/module, new permission, plugin or expo-build-properties changes, newArchEnabled). Those require a brand-new App Store / Play build.
* Never lower or reuse Android versionCode. Google Play permanently rejects a reused or lowered code. The next native bump must be versionCode ≥ 39.
* Force-update version-gate landmine. The app sends a hardcoded X-App-Version of 1.1.0 baked into the bundle. Do not raise MIN_APP_VERSION above 1.1.0 while iOS build 29 is live — the gate can't tell builds apart and would brick every live user. Leave it untouched.
* An OTA replaces the entire bundle for its runtime — it is not a patch. Always publish the full current tree (see the build29-delivery method), never a cherry-picked from-base rebuild, or you silently revert every prior OTA.

Emergency Rollback
app.json runtimeVersion is permanently 1.0.0 — no app.json change needed.
Roll back to any checkpoint by republishing its group:
cd artifacts/cashclip
PATH=/tmp/fake-bin:$PATH EXPO_TOKEN=$EXPO_TOKLAST pnpm exec eas update:republish \
--group <GROUP_ID> \
--message "ROLLBACK to <GROUP_ID>" \
--non-interactive

To roll back to the pre-reconcile state (Jun 12 cleanup):
PATH=/tmp/fake-bin:$PATH EXPO_TOKEN=$EXPO_TOKLAST pnpm exec eas update:republish \
--group 875823df-0384-48fc-b65f-5d56a9124987 \
--message "ROLLBACK: Jun-12 cleanup" \
--non-interactive


Rules
* Never lower runtimeVersion — 1.0.0 is permanent for all current live builds.
* Never reuse a versionCode on Android (Play rejects it).
* OTA only covers JS/assets — any native change needs a new App Store/Play Store build.
* After any rollback, verify on-device: delete app → reinstall → open twice.
* EAS OTA Publish workflow is one-shot — restarting it fires a live publish immediately.
